以 `.aseprite` 为主要资产；每个源文件只有一个正式 GIF。图像分析、部件组合与动画制作由 Codex 完成，Serpent 负责保存、关联和展示。

## 制作

1. 确认目标库和本次范围。检查原始图像/精灵图；已有源文件用 `scripts/assets.py inspect` 读取图层、标签和帧时长。图层使用一基层级路径标识，避免重名层或重名动作被误选。
2. 由 Codex 判断帧矩形、基准点、图层/部件和动作。不能从像素或元数据确定的帧率、动作边界或部件关系，向用户询问后再制作。方向、成长阶段、皮肤差异本身不等于动画。不要使用生成式绘图重画或补帧。
3. 按 [包契约](references/package-contract.md) 写转换清单和预览配置。多 PNG 和精灵图均使用显式帧顺序、裁切矩形和位置；保留画布对齐、透明像素和原始部件。已有 Aseprite 只复制，不保存回原文件。
4. 用 `scripts/assets.py prepare` 在独立工作目录制作源文件与唯一 `preview.gif`。最多四种组合、两种动作；各格共用动作顺序和时间轴，不强制凑满四格。已有 idle/walk 时优先抽样这两个动作。检查预览，核对像素、透明度、顺序、位置和时长。GIF 的 10ms 时间量化使用累计误差补偿，源文件保留精确时长。
5. 用 `scripts/assets.py import --run … --library …` 通过 MCP 托管导入。脚本逐块回读源和 GIF，核验摘要、配置、生成记录及唯一资产关联，然后清理本次工作目录，再回读核验。失败时保留工作目录和恢复清单，报告具体阶段，不声称完成。

## 更新

使用 `scripts/assets.py update --library … --asset …`，或先用 MCP 搜索/列出源资产，再逐个更新。更新从库内读取源文件、配置及生成记录；内容摘要、配置摘要、生成器版本均未变化且预览存在时跳过。配置可通过 `--recipe` 显式替换。

更新只上传 GIF 和配置，不替换源文件，也不重建资产，因此保留资产 ID、标签、评分和收藏。分块暂存与发布使用独立的源版本和摘要围栏；源在生成期间发生变化时停止本轮发布，保留可恢复记录。用户取消时撤销暂存，保留必要本地恢复资料。浏览、扫描或打开查看器不执行此 Skill。

## 执行与恢复

运行 `python3 scripts/assets.py --help` 查看参数。需要 Aseprite CLI；通过 `--aseprite` 或 `ASEPRITE_BIN` 指定可执行文件。连接通过 `SERPENT_MCP_URL`、`SERPENT_MCP_TOKEN` 环境变量传入；不要把令牌写入清单、日志或提交。

默认完成核验后自动清理。`--keep-work` 仅用于明确要求保留产物或诊断。原始目录、库内正式文件、项目 Skill、旧任务成果均不属于本次清理范围。清理只接受脚本创建的带所有权标记的工作目录，先完整预检路径与符号链接；失败时保留恢复信息。重新运行 import 会复用清单中的幂等键；更新失败后应使用 `resume --run …` 续传同一次运行。详情见 [包契约](references/package-contract.md)。
