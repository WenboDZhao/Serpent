# 整理、排重与标签规则

## 范围判断

| 内容 | 处理 |
| --- | --- |
| 静态图、SpriteSheet、GIF、Aseprite、PSD、可独立使用的贴图 | 图像候选；查看内容后分组 |
| `.shader`、`.shadergraph`、`.shadersubgraph`、`.gdshader`、`.gdshaderinc`、GLSL、HLSL、WGSL 等 | Shader 候选；保留类型、目标平台与依赖记录 |
| Unity/Godot 工程、Scene、Prefab、脚本、资源配置、生成缓存 | 排除；必要元数据可只读分析 |
| FBX、OBJ、Blend、骨骼工程、音频、视频、字体、普通文档 | 排除；不因能生成封面就转为图像入库 |
| JSON、`.meta`、Atlas、Plist、GameMaker 元数据 | 辅助材料；核实是否真的包含 rect、pivot、帧序或时长 |
| README、LICENSE、作者与下载信息 | 关联至来源记录；不单独创建卡片 |
| ZIP、7z、RAR 等 | 先列目录，再决定需解出的图像；压缩包本身不作正式资产 |
| `.DS_Store`、`._*`、`__MACOSX` 等 | macOS 附属文件，排除 |

不要因为路径包含 Unity、Godot、Assets 或“参考”就排除其中全部 PNG；也不要因为后缀是 PNG 就收录已识别的引擎生成缓存。扫描器只提供候选与初步分类，Codex 按上下文复核。无法识别的类型记为待处理；扩展名与文件头不一致时只在 staging 副本上修复，原件不重命名。

Shader 可按原文件收录，但 ShaderGraph、include、SubGraph 和纹理依赖并不自动成为一个 Serpent 原生关联包。记录依赖、目标引擎与原相对路径，核实托管后的完整性；能力不足时报告待处理。当前源码的文本扩展名集合没有专用 Shader 扩展，不承诺文本查看器或实时 Shader 预览，不用 `.txt`、PNG 或 Aseprite 伪装它。需要图像依赖时，按图像规则复用、入库并记录对应资产。

解压只允许进入本次工作目录，预检绝对路径、`..`、符号链接、大小写/Unicode 名称冲突，并限制文件数量、解压后总大小和嵌套层数；预算按压缩包实际规模确定。没有完整验证的解包工具时停止该包，不能直接执行资源内的脚本、安装器或引擎工程来“看看结果”。

## 逻辑资产的边界

- 一个可辨识人物/动物优先一包，容纳完整动作、方向、头像、换色与所属部件。明确属于不同人物的独立造型可以分别收录。可合成系统保留身体、衣服、头发等图层，不为每种排列创建人物。
- 一个可独立使用的动态环境对象或特效优先一包；独立使用的部件可以单列，并标为部件。不要把同名的不同效果互相覆盖。
- 静态建筑、植物、道具在边界明确、独立使用时可以拆出；地形拼接、AutoTile、九宫格、密集物品 Atlas 默认保留图集关系。记录切片 rect、原画布、pivot、图层与来源；裁切不能丢失阴影、发光、武器或帧间偏移。
- 成长阶段、朝向、开关和损坏状态是状态集合；只有确认有运动时间序列才标“动画”。静态姿态包可使用 Aseprite 保存，但标签仍写“静态姿态”。
- 多个原 Aseprite 分别保存同一人物的不同动作时，可以在新源中整合；保留原图层、时长和独有内容，记录动作来源。已有完整源只复制；都不保存回原始文件。
- PNG/GIF 与源文件配对前核对内容。预览 GIF 不重复创建卡片；原 GIF 是唯一完整动画来源时，先验证所有帧、透明度和时长再转成 Aseprite。

## 排重与版本

1. SHA-256 相同表示字节相同。保留全部来源路径，合并适用的来源/用途记录；使用语境不同的同图不静默丢失语境。
2. 同画布的解码像素可发现重新编码的复本。辅助指纹只生成候选：色彩、位深、透明度、画布和可编辑结构仍要检查。禁止用裁掉透明边、缩放或感知相似度直接决定删除。
3. 帧集合、SpriteSheet、拆帧和头像按主体关系合包。源文件拥有隐藏层、独有动作或额外变体时，不能因预览相同就判重复。
4. 优先作者明确版本及更新说明，其次内容覆盖与完整性；mtime、文件名数字只作线索。版本“较新”但缺旧版独有内容时补留，不机械保留最大数字。
5. 旧来源清单只证明见过文件，最终导入清单和库内回读才证明已入库。新增目录与旧目录相同的包里，可能有以前范围外、仍未收录的文件；本 Skill 仍只处理图像和 Shader。

每个合并或排除决定记录可检查的理由，例如相同 SHA-256、逐帧覆盖、明确作者版本信息或“旧文件仍有独有动作”。证据不足时保留候选/待处理，避免误删换色、皮肤和追加包。

`sources` 中登记了文件，不等于它的内容已经进入主要资产。同名的原生 Aseprite、PNG 导出、分方向条带与整张总图可能各有独有帧；逐格核对 RGBA、位置、完整覆盖与时长，记录原 rect 到正式源帧/图层的对应。整图不能仅凭某一帧匹配就判重复。不同导出版本使用唯一标识，避免写入同一个变体名而覆盖前一套帧；没有明确动作含义的独有格可作为静态补充姿态保存，不猜动作边界。

## 标签与目录

先分页读取库内标签，复用词汇和人工选择。斜线是名称前缀约定，不假定 Serpent 提供真实的标签父子层级。目录建议“来源素材包/主类别”，通常两层足够；同一资产的多重属性使用标签，避免复制进多个目录。

| 维度 | 示例 |
| --- | --- |
| 媒体 | `图像`；Shader 使用 `Shader`，不添加 `图像` |
| 来源 | `素材包/作者原名`、有证据的 `来源/作者名` |
| 图像主类别 | `类型/人物`、`类型/动物`、`类型/植物`、`类型/大型建筑`、`类型/环境装饰`、`类型/地形`、`类型/UI`、`类型/道具`、`类型/特效` |
| 人物/动物 | `人物/村民`、`人物/忍者`、`动物/牛`、`动物/野猪`、`动物/鸟类` |
| 植物/建筑 | `植物/树木`、`植物/花卉`、`植物/作物`、`建筑/房屋`、`建筑/城墙` |
| 环境/地形 | `环境/家具`、`环境/岩石`、`环境/阴影`、`地形/水域`、`地形/森林` |
| 其他内容 | `道具/武器`、`UI/九宫格`、`特效/烟尘` |
| 风格/视角 | `风格/像素`、`风格/Q版`、`视角/俯视`、`视角/侧视` |
| 特征 | `特征/动画`、`特征/静态姿态`、`特征/可合成`、`特征/多方向`、`特征/含头像`、`特征/图集`、`特征/部件` |
| 用途 | `用途/参考`，依据本次任务或内容判断 |
| Shader | `Shader/水面`、`Shader/描边`、`引擎/Unity`、`引擎/Godot`，仅有对应证据时分配 |

动物、植物等内容标签服务于图像，Shader 使用自身标签。每项至少有媒体标识、内容类别和来源信息；来源不明时明确记录未知，不杜撰作者。风格、视角、特征按实际添加。每帧动作名保存在 Aseprite，避免给人物卡片堆积数十个动作标签。

中文、英文名称归一时保留作者原名与搜索别名记录，不批量改写库内其他资产或清除人工标签。来源说明、许可原文和用途分开记录；不从“免费”“已购买”或“参考”目录名推断授权条款。
