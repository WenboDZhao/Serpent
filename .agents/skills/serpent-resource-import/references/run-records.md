# 运行记录与增量处理

记录目录由本次任务确定，必须持久、可找回，并与原始目录、临时制作目录、Skill 目录分开。可以按 `libraryId/runs/runId` 组织；MCP 不返回库内绝对路径，不必为记录而查询或直接读取库数据库。

最小记录组成：

- `inventory.jsonl`、`summary.json`：源位置、文件大小/时间与摘要、范围判断、扫描是否完整。
- `plan.json`：逻辑主体 key、原始文件/依赖、选择版本的理由、目标目录/名字、标签与处理方式。
- 请求与回执：按主体或批次保存完整领域请求、幂等键、调用返回和恢复引用；不保存 transport header、Bearer、token 或 session。
- `events.jsonl`：使用 `checkpoint` 追加阶段事实与证据摘要。修改方案后记录新的计划摘要，不能覆盖旧请求然后继续使用旧幂等键。
- 最终导入清单：实际 `libraryId`、逻辑 key、assetId、实际 displayName、文件夹 ID/路径、实际标签、源/预览摘要、配置与生成器版本、来源与许可记录、核验及清理结果。
- 用户可读报告：实际完成/复用/排除/待处理数量，未覆盖环境，恢复方法。

静态资产也保留内容摘要和人工元数据快照；动画另外保留 recipe、generation 及现有动画 Skill 的恢复路径。成功后长期保留可追溯的精简事实，拆帧、源副本和调试图属于可清理临时物。

## 增量决策

1. 用已有逻辑 key 和源身份定位旧记录；路径迁移只更新来源定位。
2. 读取库内实际 ID、标签、版本和文件；记录不存在或资产被用户删除时，不假定可直接复用。用户删除可能是有意操作，先报告该组。
3. 源内容、有效整理策略、预览配置与生成器版本均未变，且库内资产/预览可读时跳过。
4. 只改标签方案时，仅补充本次计划需要的标签；先读现状，保留用户新增内容。不要因文件没变而跳过尚未完成的标签或目录步骤。
5. 只改动画预览时，调用动画 Skill 的 update/resume，不替换源、不新建 ID。源有改动时先核对版本和独有内容，再通过当前公开能力更新；不能保持身份或存在并发冲突时停止该组并保留旧资产。
6. 新版本是追加动作或缺少旧内容时，整理出包含所需独有内容的新源后再考虑更新。相似图或文件名相同不构成替换依据。

## 状态的含义

| 阶段 | 必须已经发生的事实 |
| --- | --- |
| `prepared` | 本地正式候选已生成，来源和输出摘要、动作/像素检查有记录 |
| `submitted` | 写操作前已保存本次精确领域请求与幂等键 |
| `imported` | 已有 MCP 回执或回读可确认的资产 ID；标签/内容核验可能未完成 |
| `verified` | 文件字节、目录、标签、动画关联等该项检查均通过 |
| `cleaned` | 只清理本次临时物，清理后正式文件再次回读通过 |
| `failed` / `cancelled` | 本阶段未完成；保留已成功资产与恢复信息 |
| `cleanup-failed` | 入库可能成功，但临时物未完全清理；不得声称全部完成 |

脚本的检查点不充当状态机或恢复执行器。Codex 必须先读证据和实际 MCP 状态，再选择下一步。单次请求内部分成功时按 assetId/主体分别记状态，不能整批标成成功或盲目重导。
