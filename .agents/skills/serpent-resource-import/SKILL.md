# 图像资源整理与 Serpent 导入

把原始文件整理成能浏览、检索、复用的资产。Codex 判断素材含义和分组，确定性脚本负责清点与检查，Serpent 通过 MCP 保存和展示。主体说明使用中文，Aseprite、Shader、SpriteSheet、MCP、文件格式及 API 名称保留英文。

## 范围与任务模式

- 收录图像及其可编辑源，包括 PNG、GIF、SpriteSheet、PSD、Aseprite 等；Shader 源文件与 ShaderGraph 是明确例外。
- Unity、Godot 的工程、Scene、Prefab、普通脚本、导入缓存和运行配置不入库；模型、音频、视频、字体同样排除。工程里的独立图像可按图像提取。JSON、`.meta`、Atlas 元数据、README 和许可文件只按需读取、保留来源记录，不生成独立卡片。细则见 [整理规则](references/organization.md)。
- 用户只要求调研或方案时，仅做只读盘点并交付方案。已授权整理导入时，持续完成准备、MCP 导入、标签、核验、清理；不要重复询问已确定的选择。
- 不确定的主体归属、动作边界、部件关系或版本覆盖，集中询问受影响的素材组；其他明确部分继续。无法确认的项目记为待处理，不猜测后丢弃。

## 工作流程

1. **盘点**：确定源目录、目标库和任务范围，读取已有导入记录与标签。运行 `scripts/catalog.py scan`，按素材包、类型和命名模式抽样查看内容；大目录使用 JSONL，分组检索，避免把整份清单载入对话。扫描不连接 MCP，不修改原文件。命令见 [清单与脚本](references/catalog.md)。
2. **理解和排重**：先定义逻辑资产，再做字节、像素和结构比较。人物、动物的动作、方向、头像与所属部件尽量整合；地形、UI 和成套图集保留使用关系。用 `duplicates` 找候选，结合内容与历史清单决定是否复用。不同造型不自动当作版本；较新包也可能只是追加动作。规则与证据要求见 [整理规则](references/organization.md)。
3. **规划**：建立 `plan.json`，为每项记录稳定 key、源文件、目标名称、目录、标签及处理理由；排除、重复和待处理项也有去向。运行 `validate-plan` 检查范围与覆盖。默认沿用库内标签词汇，只补充实际需要的新标签。
4. **制作**：静态图保留原格式与像素；对图集是否拆分作明确判断。动画和静态姿态包调用项目内 [aseprite-animation-assets](../aseprite-animation-assets/SKILL.md)，不复制它的转换代码。一个 Aseprite 源关联一个 GIF，最多四种组合、两种动作。保留作者时长；无时长时默认每帧 100ms，可由本次任务覆盖。朝向、换色、成长阶段和状态不自动成为运动动画。
5. **导入与标签**：按 [MCP 工作流](references/serpent-workflow.md) 发现当前工具、显式传入 `libraryId`，使用托管复制导入。先持久记录精确请求和幂等键，再发送写操作。静态图的 staging 名称避免数字结尾导致误合并为序列图。Shader 保留真实扩展名，并如实说明当前 Serpent 的显示能力；不能假定支持实时渲染。
6. **核验**：回读实际资产 ID、文件内容、目录、标签；动画还核对源/GIF/配置/生成记录及像素、位置、帧序和时长。来源复本相同不等于整个素材包已入库。已有资产更新保留人工标签、评分与收藏，无法安全保持 ID 的替换留待处理。
7. **清理与交付**：只有托管核验通过才删除本次拥有的临时文件，并在清理后再次回读。长期保留来源摘要、导入对应关系、排重理由及结果，不保留冗余拆帧、调试图和试验 GIF。中断、部分完成或清理失败保留恢复记录，准确报告阶段。恢复细则见 [MCP 工作流](references/serpent-workflow.md)。

## 可复用记录

记录放在独立于原始目录、临时目录和 Skill 的持久位置，按 `libraryId` 与运行 ID 区分。协议见 [运行记录](references/run-records.md)。不要硬编码本机路径、MCP 端口、凭据、库 ID 或上次的素材数量。

每次运行至少交付：实际完成/复用/排除/待处理数量、目录与标签说明、原文件是否变化、核验结果、清理结果和记录位置。增量任务比较源内容、整理规则及生成器版本；只扫描到路径变化时，重新定位与核验，不直接新增卡片。
